# 书源脚本引擎设计（M2 v2）

日期：2026-10-25 · 状态：设计已确认，待实施计划

## 0. 背景与目标

现行规则引擎（cheerio 选择器 + 链式取值 DSL）在调试幽香书房时暴露死穴：加密 AJAX 搜索（`_t/_ts/_s` token）、onclick base64 跳转、`{page}` 模板最大页码反推等全靠引擎堆特例。改为 **JS 脚本书源**：每个源是一个 class，四个阶段方法（搜索/详情/目录/正文），特例逻辑归源，引擎只留沙箱、编排与通用净化。

## 1. 决策记录（已拍板）

| 决策点 | 结论 |
|---|---|
| 方法名 | `search` / `getDetail` / `getChapters` / `getContent`（全可选，缺 = 能力不支持） |
| 格式 | 单 JS 文本存 DB + 落盘 `data/sources/{id}.js`，`export default class Source` |
| 配置 | 类成员声明（`base`/`headers`/`replace`），引擎只读，**无构造器注入** |
| 翻页 | 引擎处理：`getChapters` 返回 `{list, next}` 引擎循环；`getContent` 可返回 `{text, next}` 引擎拼接 |
| 净化 | `replace` 成员 = `{regex, replacement}` 对象数组，引擎在正文合并后自动应用 |
| 执行 | 动态 import + 缓存（id+mtime 失效），Promise.race 超时；不做 Worker 隔离（源自用，半可信） |
| 旧规则源 | 编辑走现有规则表单，保存时**转换器生成 .js**（头标 `// GENERATED by rules`），JS 不可手改 |
| 新 JS 源 | 直接编辑 class，保存落盘生效 |
| Playwright | M2 不做，接口预留（以后作为可选依赖懒加载） |
| 字段命名 | camelCase：`detailUrl`/`tocUrl` |

## 2. 脚本格式

```js
// @name 幽香书房
export default class Source {
  base = "https://yxshufang.com";            // 相对 URL 补全默认 base
  headers = { Cookie: "..." };               // 引擎注入到每次 fetchText
  replace = [                                // 正文净化，引擎在合并后统一应用
    { regex: "广告链接：.*", replacement: "" },
  ];

  async search(name, page = 1) {
    // 返回 [{ title, author?, desc?, cover?, detailUrl }]  detailUrl 必填
  }
  async getDetail(url) {
    // 返回 { title?, author?, desc?, cover?, tocUrl }  tocUrl 缺省 = url
  }
  async getChapters(url) {
    // 返回 { list: [{ title, url }], next? }  next 空/无 = 结束；翻页由引擎循环
  }
  async getContent(url) {
    // 返回 string（无翻页）或 { text, next? }（章节内部翻页，引擎拼接）
  }
}
```

- 四个方法全部可选：无 `search` → 不参与搜索聚合与换源候选（幽香书房现状）；无 `getChapters`/`getContent` → 不能入库读书
- 错误：`throw new Error("原因")` 引擎捕获进日志；`log(msg)` 打调试日志
- 职责边界：广告剔除等站点特定清洗源自己做（replace 成员或方法内处理）；行 trim、`\n` 归一、占位检测、字数校验引擎统一做

## 3. 引擎注入 API（源内可用）

```js
const res = await fetchText(url, { method?, headers?, body? });
// → { status, text, url }  url=重定向后最终地址；charset 解码/限速/重试/日志引擎做
const $ = parse(res.text);   // cheerio load
abs("/book/1", res.url);     // 相对→绝对，base 参数缺省用源.base
log("调试信息");
```

另有规则兼容 helper（供转换器生成的代码使用）：`ruleList(nodes, bookList规则)`、`ruleText(nodes, 规则)` 等薄封装——直接复用现有 rule.ts 求值器，规则字符串原样可用（`||`、`##`、`{{key}}` 均已实现）。

## 4. 执行流程

```
保存源 → sources 表落库（type/code/json）→ 写 data/sources/{id}.js
调用 → 动态 import(path)（模块缓存按 id+mtime 失效）→ new Source() → 读成员 → 调方法
超时 → Promise.race 报错（不能真中断，自用可接受；升级 Worker 为后续项）
```

## 5. 数据模型与引擎接口

- sources 表加列：`type`（"rules" | "script"，默认 rules）、`code`（script 源码文本）
- 现有引擎入口 `searchSource / getBookInfo / getToc / getContent` 签名不变，内部按 type 分流：
  - rules → 现有规则引擎（暂留，跑稳一版后评估删除）
  - script → 脚本引擎：适配 class 方法到现有返回类型，保证缓存/退避/进度/换源全链路不动
- 正文落地 `fetchAndSave`、全本缓存 `runCacheJob`、书架快照逻辑零改动

## 6. 编辑器 UI（Sources.tsx）

- 旧规则源：现有表单 + JSON 面板不变；JS 选项卡只读预览生成的代码
- 新 JS 源：代码编辑器（textarea 即可），无规则表单
- 新建源时选类型；保存即重新生成 .js 并失效 import 缓存
- 调试链路（debug-search / debug SSE）不变，script 源走脚本引擎

## 7. 规则 → JS 转换器（scripts/convert-rules.ts）

| 规则制 | 生成的 JS |
|---|---|
| `searchUrl + {{key}}/{{page}}` | 模板字符串拼 URL（走 fetchText） |
| `ruleSearch.bookList` + 字段规则 | `parse` + 循环 + `ruleText/ruleAttr` helper 调用 |
| `||` 回退、`##正则##替换##变换` | helper 已实现，规则字符串原样嵌入 |
| `ruleBookInfo` 各字段 | `getDetail` 内逐字段 helper 调用 |
| `ruleToc.nextTocUrl` 翻页 | `getChapters` 内 while 循环取下一页 |
| `ruleToc` 的 `{page}` 模板 | while 循环展开（最大页码反推逻辑源内 3~5 行） |
| `ruleContent.nextContentUrl` | `getContent` 返回 `{text, next}` |
| `replaceRegex` | class `replace` 成员 |
| `header` 字段 | class `headers` 成员 |

一次性转换存量源（sto66 id=2、幽香书房 id=3）生成 .js，人工过目后切 type=script；规则引擎标废弃。

## 8. 不做的事（M2 边界）

- Worker 强隔离（源自用；分享市场再议）
- Playwright/无头浏览器渲染（接口预留）
- 源市场/签名校验
- 删除规则引擎代码（只标废弃，观察一版）

## 9. 验收标准

1. `bun test` 全绿：脚本引擎单测（本地 fixture 站点 + mock class 源）覆盖四方法、翻页、超时、缺方法降级
2. sto66/幽香书房转换后全链路可用：搜索（sto66）、详情、目录（幽香书房 {page} 翻页）、正文（幽香书房 Cookie 过 WAF）
3. 幽香书房搜索经 JS 算出 `_t/_ts/_s` token，搜索结果非空（规则引擎做不到的事，作为脚本引擎的标志性验收）
4. 书架/阅读/缓存/换源界面零回归
