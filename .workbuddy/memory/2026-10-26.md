
## API 网关前缀 /gw/reader（4fc924c）
- 用户要求前端请求统一走 /gw/reader 前缀；dev 由 vite 代理转发到 http://192.168.1.124/gw/reader（网关不剥前缀）
- 实现：web/src/api.ts 加 API_BASE = import.meta.env.VITE_API_BASE ?? "/gw/reader"，api() 统一拼前缀；Search.tsx / Sources.tsx 两处裸 fetch（SSE 流式）也改；vite proxy "/gw/reader" → http://192.168.1.124（target 只填 host，路径原样保留）
- 后端 index.ts 加别名路由 /gw/reader/auth + /gw/reader/api，与 /api /auth 等价——网关直接转发不剥前缀也能命中；本地直连不受影响
- 本地调试绕网关：web/.env 设 VITE_API_BASE=""（空串）走同源 /api + localhost:8094 代理
- 冒烟：临时端口 8095，/gw/reader/api/ping、/gw/reader/auth/me 均 401（路由命中、鉴权正常）；49 测试 + 前后端 tsc + build 全绿
